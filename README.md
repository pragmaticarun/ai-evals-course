# AI Evals, Hands-On

An original, self-paced course on evaluating LLM agents. You build one running agent, **MediaDoctor**
(Android and multimedia debugging assistant on Claude), and take it through the whole loop: analyze failures,
measure them with evaluators you trust, and improve with evidence.

Site: https://pragmaticarun.github.io/ai-evals-course/ ·
[Start here (13-week study plan)](https://pragmaticarun.github.io/ai-evals-course/start-here/) ·
[Capstone reference report](https://pragmaticarun.github.io/ai-evals-course/capstone/)

**Status:** all 12 modules are available (about 87 hours at about 7 hours a week). Versions last checked
**2026-11-23** (see [Versions checked](https://pragmaticarun.github.io/ai-evals-course/versions/)).

> **The data is synthetic.** MediaDoctor's questions, knowledge base, scenarios, and attack cases were written for
> the course by the scripts in `scripts/`. Every recorded model response (agent turns, judge verdicts, synthetic
> queries) was then generated by Claude subagents standing in for the API, Sonnet for the agent and Haiku for the
> judges and synthetic data, and is labelled `"source": "subagent-authored"`; the reference labels were written by
> Claude Opus subagents (see `scripts/subagent_harness/`). That keeps every lab reproducible offline. No failures
> are planted, and these agents fail rarely (for example 3 of 100 module 3 traces), so several labs have few
> failures to find and say what the method would show on data with more. The numbers describe the methods on this
> data, not how Claude models behave through the API; re-record live before relying on any of them. The code
> (agent, tools, checks, judges, statistics, CI gate) is real.

## How to run it

Ubuntu (or any Linux or macOS) with `git` and [uv](https://docs.astral.sh/uv/). No API key is needed for anything
in this section.

```bash
git clone https://github.com/pragmaticarun/ai-evals-course.git && cd ai-evals-course
uv sync                                   # Python 3.14 + pinned deps from uv.lock
uv run pytest -q                          # the whole test suite, offline (about a minute)
uv run pytest evals -q                    # the eval suite (fast tier and judge tier, replayed)
uv run ruff check . && uv run ruff format --check .
uv run zensical build --clean --strict    # the site, as CI builds it (fallback: uv run mkdocs build --strict)
uv run zensical serve                     # the course site at http://localhost:8000
uv run mediadoctor-capstone run           # the whole eval loop, modules 1 to 11, in a few seconds
```

## Replay, record, and live

Every Claude call in the course goes through `evalkit.LLM`, whose mode comes from `EVALS_LLM_MODE`:

| Mode | What it does | Needs | Used by |
|---|---|---|---|
| `replay` (default) | Looks each request up in `fixtures/recorded/` by the SHA-256 of its canonical JSON. Never touches the network; a request with no recording raises `FixtureMissingError`. | nothing | every lab, every test, and CI |
| `record` | Calls the Anthropic API and saves each response under its request key. | `ANTHROPIC_API_KEY` | re-recording a lab; the manual `live-evals.yml` workflow |
| `live` | Calls the API and saves nothing. | `ANTHROPIC_API_KEY` | trying a prompt without saving anything |

Record and live mode call **`claude-haiku-4-5` only** (`[live]` in `config/models.toml`): every request is sent to it
whatever its role, and any other model (Opus, Fable, Sonnet, Haiku 5.5) is refused before the request leaves the
machine. Replay is unaffected. Recordings are keyed with Haiku 4.5; replay your own with `EVALS_REPLAY_LIVE_MODEL=1`.
Live runs therefore compare prompts and strategies, not models, and prompt caching will not cache (Haiku 4.5 needs a
4,096-token prefix).

Put the key in your shell or a git-ignored `.env`, never in a committed file (CI runs gitleaks). Record into a
directory under `runs/` (git-ignored) rather than over the course fixtures, because the tests pin the synthetic
numbers. Most labs end with an optional section showing how, and module 12's
[Make it your own](https://pragmaticarun.github.io/ai-evals-course/modules/12-capstone/extensions/) covers a full
live re-record. Models are set per role in `config/models.toml` (agent `claude-sonnet-5-5`; judge and synthetic
data `claude-haiku-5-5`), and so are each model's thinking and effort settings (`[generation.<model>]`), which
`evalkit.LLM` adds to every request. Changing them changes every request key: re-record, or for the synthetic
fixtures run `uv run python scripts/migrate_fixtures_generation.py`.

## Commands by module

```bash
uv run mediadoctor-lab01 compare v1 v2    # the module 1 worked example
uv run mediadoctor-lab02 run --out runs/t.jsonl   # module 2: tool-using agent, traced
uv run evalkit view runs/t.jsonl m2q03    # read one trace in the terminal
uv run mediadoctor-lab03 rank             # module 3: ranked failure modes from the reference labels
uv run mediadoctor-lab03 annotate --labels runs/m3_labels.csv   # label the 100 traces yourself
uv run mediadoctor-lab04 generate --out runs/m4_v1.jsonl   # module 4: tuples -> synthetic queries -> dataset v1
uv run mediadoctor-lab04 coverage         # coverage matrix of the frozen dataset
uv run mediadoctor-lab05 validate --split dev   # module 5: LLM judges vs human labels (TPR/TNR)
uv run mediadoctor-lab05 estimate         # judge-corrected pass rate with a bootstrap CI
uv run mediadoctor-lab05 ppi              # the same budget of labels with PPI / PPI++ instead
uv run mediadoctor-lab06 modes            # module 6: prompt v1 vs v2 per failure mode, paired tests
uv run mediadoctor-lab06 report --out runs/m6_report.md   # metric report with confidence intervals
uv run mediadoctor-lab07 retrieval        # module 7: recall@k, MRR, nDCG for 4 chunking/ranking configs
uv run mediadoctor-lab07 agents           # planner + specialists: transition-failure matrix
uv run mediadoctor-lab07 report --out runs/m7_report.md   # RAG, multi-turn, multi-agent, and vision evals
uv run pytest evals -m "not judges"       # module 8: the eval suite's fast tier (the judge tier: -m judges)
uv run mediadoctor-lab08 gate --prompt v2 # the regression gate on a prompt change (warns: exit 0)
uv run mediadoctor-lab08 hygiene          # leakage, contamination, and stale-label checks on the golden set
uv run mediadoctor-lab09 monitor          # module 9: a simulated production week: drift, control charts, CUSUM
uv run mediadoctor-lab09 sample           # the review queue: signal-triggered + random + stratified picks
uv run mediadoctor-lab09 annotate         # the trace review app at http://127.0.0.1:8009 (localhost only)
uv run annotate serve --help              # the same app on any trace store
uv run mediadoctor-lab10 surface          # module 10: the attack surface map
uv run mediadoctor-lab10 report           # attack success rate and benign false positives for guardrails none/v1/v2
uv run mediadoctor-lab10 hitl --approver ask   # be the human approving (or not) a risky tool call
uv run mediadoctor-lab10 gate             # the red-team CI gate (also in `pytest evals`)
uv run mediadoctor-lab11 report           # module 11: success CI, p50/p95, cost per successful task for 7 configurations
uv run mediadoctor-lab11 pareto --svg runs/m11/pareto.svg   # the accuracy vs cost frontier
uv run mediadoctor-lab11 memo             # draft the one-page decision memo from the pre-registered rule
uv run mediadoctor-capstone slices        # module 12: baseline vs candidate per topic, to choose a slice
uv run mediadoctor-capstone report --slice drm-resolution --out runs/capstone/report.md   # the eval report (dev only)
uv run mediadoctor-capstone check runs/capstone/report.md   # self-review against the eval report template
```

No API key is needed for any of the above. See `docs/setup.md` for the full setup.

## Layout

```text
config/models.toml        Claude model per role (agent; cheaper judge and synth), thinking and effort per model, and prices including prompt-cache rates
config/synth/             test dimensions and exclusion rules for synthetic data (module 4)
config/judges/            versioned LLM judge specs: criterion, PASS/FAIL, context, train-split examples (module 5)
config/release.toml       the prompt MediaDoctor ships; the eval gate compares changes to it (module 8)
config/eval_gate.toml     the eval gate's tiers, rule, and budgets (module 8)
config/redteam/           the attack suite's dimensions and the red-team gate (module 10)
config/experiments/       module 11's configurations, pre-registration, and experiment log
docs/capstone/            the module 12 reference eval report (generated; a test checks it is current)
docs/                     course site (Zensical, Material-compatible mkdocs.yml)
labs/evalkit/             record/replay LLM wrapper, fixtures, tracer, trace viewer, OTLP export, annotation and taxonomy tools, synthetic data (tuples, batching, dedup, coverage, splits), judges (prompts, TPR/TNR), statistics (Wilson and bootstrap CIs, judge-error correction, McNemar, Holm, pass^k, sample sizes), retrieval metrics, trajectory metrics and transition-failure matrices, regression gates, golden manifests, dataset hygiene, production sampling and drift (PSI, p-charts, CUSUM), Cohen's kappa
labs/mediadoctor/         the running agent (module 1 seed; module 2 Claude tool-use agent with 4 tools; module 7 RAG, chat with a simulated user, planner + specialists, vision; module 10 action tools and guardrails, simulated; module 11 experiment configurations, cascade and retry strategies; module 12 capstone pipeline and report generator)
labs/annotate/            the trace review app (FastAPI + HTMX, keyboard-driven, localhost only; module 9)
data/kb/                  knowledge-base notes the agent retrieves from
data/kb_v2/               second-edition knowledge base (25 docs, 57 sections) for the module 7 retrieval evals
data/sessions/            multi-turn chat scenarios for the simulated user (module 7)
data/datasets/            versioned case sets (module03_cases.jsonl: 100-trace error-analysis set; module04_v1.jsonl: synthetic dataset v1 + manifest)
data/synth/               stand-in "beta" queries used as style examples and seeds (written by the course scripts)
data/labels/              reference annotations (written by Claude Opus subagents) and failure-mode definitions
data/golden/              the golden set's manifest, labelled-answer digests, hygiene review (module 8)
data/production/          a simulated week of production traffic built from the recorded traces, and the AV1 drift cases (module 9, synthetic)
data/redteam/             the adversarial suite and benign traffic, injected clips, logs, poisoned KB notes, a fake workspace with canary secrets (module 10, written by the course scripts)
data/media/               small ffmpeg-generated sample clips + cached ffprobe output; frames/ has module 7's test frames and spectrograms
data/devices/, data/logs/ fictional device codec tables and synthetic logcat captures
fixtures/recorded/        SHA-256 keyed JSONL recorded responses (replayed in CI)
scripts/                  maintenance scripts (original fixture authoring, the subagent harness that regenerated the fixtures and labels, version report)
tests/                    pytest suite, offline (includes docs checks: nav, solutions, synthetic-data notices)
evals/                    the eval suite as pytest tests (fast and judge tiers), the red-team regression tests, and the committed baselines (modules 8, 10)
.github/workflows/        ci.yml, deploy.yml (GitHub Pages), eval-gate.yml (module 8 gate), live-evals.yml (manual)
```
